# 开工计划与第一版范围

状态：产品方向、技术路线和公司内开发发布方式已确认。以下实施顺序与首轮范围是建议基线，可以根据公司环境作小范围调整。

## 已确认的决定

- 第一目标是解释 API 的 request/response Schema、调用顺序、业务流程和状态变化。
- 知识库、笔记、排障记录、工作总结与成果材料同样需要逐步积累。
- 公司内公开阅读，单人编辑；实际开发和发布全部在公司环境完成。
- 使用 Git 保存内容，网站承担阅读、检索和交互展示。
- Astro + Starlight 为技术路线，采用本地搜索和静态发布；不深度改造底层文档布局。
- 知识库和展示库作为主要内容入口，通过项目筛选或汇总页建立关联。
- 权威资料可以继续保留在 Confluence、接口平台等现有系统，门户保存解释和链接。
- 展示允许作为阶段快照保存，不要求随 API 代码实时更新。
- 以站点链接分享为主，兼容少量独立 HTML。
- AI 可以根据指定代码生成说明，也可以整理作者提供的草稿、样例、ticket 和任务细节。
- 工作总结由已有内容与补充工作记录整理得到；作者核对后发布。

## 第一版建议范围

1. 简洁首页：近期内容、常用入口和项目入口。
2. 知识库：分层目录、正文、代码块、页内导航。
3. 展示库：条目列表、项目关联、历史快照标识。
4. 一张交互说明页：Schema、调用步骤、正常与异常状态变化。
5. 轻量工作记录：背景、作者贡献、结果、证据链接。
6. 全站搜索：知识库正文，以及明确收录的展示和工作记录文本。
7. 独立 HTML 示例：可从展示条目打开，并返回门户。
8. 内容模板及 Agent 整理流程。

首轮使用标记清楚的虚构内容。无需用户先提供真实业务案例。

后台管理、多人编辑、实时调用业务 API、全量扫描业务仓库和无人审核发布不属于当前首轮目标。定时整理在手动流程可用后再评估。

## 实施顺序

| 阶段 | 工作 | 完成标志 |
| --- | --- | --- |
| 环境核验 | 阅读公司规范、确认工作区、检查仓库、运行时、包源及可用发布方式 | 明确已知条件与实际阻塞项 |
| 基础站点 | 初始化兼容依赖，完成导航、知识库与搜索 | 公司开发环境中可预览，正式静态构建成功 |
| 代表性内容 | 添加文档、交互演示、独立 HTML、工作记录 | 直接访问、栏目切换和项目关联可用 |
| 整理流程 | 落实内容模板、发布状态、Agent 工作约定 | 新增与更新内容可预览、可检索，归档保留链接 |
| 内部发布 | 按公司实际能力配置构建发布 | 内部真实访问地址、深链接、资源和搜索通过验收 |

环境核验采用实际证据。有仓库或平台入口后，优先查看现成配置，不要求用户猜测工具版本或平台能力。

## 可采用的默认值

- 中文界面，保留英文 API 名称、代码和技术术语。
- 电脑阅读与屏幕共享优先，手机可正常阅读与操作。
- 统一字体、颜色、导航和内容元信息；展示使用宽幅内容区。
- 演示采用预设数据；静态资源随站点发布，减少对外部 CDN 的依赖。
- 门户显示名称暂定“工程手记”，仓库名 `engineering-notebook`。
- 最终视觉风格依据实际页面调整，不照搬参考文档站或早期布局示意。

内容规则以 [content-model.md](content-model.md) 为准；页面组织以 [ui-direction.md](ui-direction.md) 为准。

## 公司环境中仍需核验

- 内部目标仓库、Pages URL 和仓库子路径。
- 已有公司模板、构建发布约定和可用执行器。
- 依赖包来源与可用版本，是否需要内部包源。
- 站点资源和搜索索引的内部访问方式。

这些属于尚未拿到环境入口的事实，不意味着技术路线或产品方向需要重新讨论。发布条件未齐时可完成公司开发环境内的站点与构建；上线状态保持未验证。

## 验收

1. 读者通过具体页面链接即可阅读；子路径部署下刷新深链接有效。
2. 顶部导航、文档目录、页内目录和返回入口有效。
3. 中文业务词、英文 API 名、字段名能找到预期示例；搜索结果跳转正确。
4. Schema 切换、正常流程、拒绝场景与重置符合示例约定。
5. 完整 HTML 可访问，其展示条目可检索；全文索引范围有明确说明。
6. 新增、更新、草稿和归档行为在正式构建中符合内容规则。
7. 电脑与手机宽度下无阻碍阅读和操作的遮挡或溢出。
8. 对实际公司 URL 做发布验收；分别报告本地验证、正式构建与上线结果。
