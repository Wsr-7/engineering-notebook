# UI 与信息结构

这是设计方向，不是最终视觉稿。框架默认主题和讨论中的早期示意都不构成最终 UI 限制。

## 统一入口，不同阅读布局

| 页面 | 布局 | 用途 |
| --- | --- | --- |
| 首页 | 内容概览与常用入口，不显示文档侧栏 | 快速找到近期协作材料与项目 |
| 知识库 | 分层目录、适宜阅读宽度的正文、页内目录 | 笔记、排障、操作说明、业务知识 |
| 展示库 | 列表或卡片，可按项目组织 | 查找联调说明、流程演示和方案讲解 |
| 展示详情 | 统一顶部导航，宽幅内容，正文自由布局 | Schema、状态变化、调用顺序、方案比较 |
| 演示模式 | 隐藏非必要导航，可随时退出 | 屏幕共享和现场讲解 |
| 工作记录 | 按时间或项目组织，关联已有内容 | 阶段记录与总结素材 |

顶部栏目保持稳定；每个 API 或一次联调生成一个内容条目，不持续增加顶部 Tab。

项目汇总页通过引用聚合相关笔记、展示和工作记录。同一正文只保存一份。

## 展示页按问题选择表达方式

- **Schema**：字段类型、必填性、业务含义与 JSON 示例对照。
- **调用顺序**：时序图、分步展示或展开式说明。
- **状态变化**：选择初始状态，观察允许动作、拒绝条件和最终响应。
- **方案比较**：并排说明约束、备选方案和选择理由。
- **普通解释**：正文、代码与图示即可，不为每页强加交互。

交互示例采用虚构数据，并明确标记。第一版不承担在线 Postman 或真实业务调用平台的职责。

## 视觉原则

- 统一导航、字体层级、颜色和内容元信息，正文按用途调整布局。
- 克制使用颜色，以内容和阅读路径为主；项目数量、成果指标等只展示真实数据。
- 知识库优先复用 Starlight 的文档结构，定制样式和必要的局部组件。
- 首页和展示页使用 Astro 页面与共享布局，避免因一个演示修改全站文档底层结构。
- 保留键盘操作、可见焦点、合理对比度以及手机上的可读性。

## 独立 HTML

完整 HTML 可以保留为独立文件，资源组织和路径由实现阶段核验。

每个独立展示通过一个可检索条目收录标题、摘要、项目与入口。适用时提供“返回门户”链接；不能自动加入共享布局的文件，不宣称已统一导航。

对文档、展示简介和独立 HTML 分别明确搜索索引范围。脚本运行时生成的文字、图片或 SVG 中的文字不默认承诺可全文检索。

## 归档展示

展示页显示制作或更新日期、适用阶段，以及可获得的版本或来源。

归档后保留原 URL，页面与搜索结果显示历史说明标记。新材料存在时可互相链接；不将归档等同于原结论必然错误。
